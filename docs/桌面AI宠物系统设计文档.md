# 桌面 AI 宠物系统设计文档

## 1. 项目概述

### 1.1 项目名称

**Desktop AI Pet**

暂定名称，后续可以自行修改。

### 1.2 产品定位

一款运行在电脑桌面上的轻量级 AI 虚拟宠物。

宠物不是传统意义上的独立窗口，而是以：

- 透明窗口
- 无边框
- 始终置顶
- 桌面自由移动
- 窗口边缘停留
- 任务栏停留
- 桌面自主活动

等方式存在于用户电脑环境中。

核心体验：

> **让用户感觉电脑里真的住着一个“小家伙”。**

---

# 2. 第一版目标

第一版不追求复杂商业化，而是以：

> **个人玩具 + 高完成度桌面体验**

为目标。

重点不是做复杂的商城、等级、充值等系统，而是把以下几个东西做好：

1. 宠物视觉表现
2. 宠物动画
3. 桌面空间感
4. 自主行为
5. 鼠标交互
6. 窗口交互
7. AI 对话
8. 宠物人格
9. 情绪变化
10. 长时间运行稳定性

---

# 3. 宠物类型

支持两种基本形态。

## 3.1 真人 / 虚拟人

例如：

- 二次元女孩
- 二次元男孩
- 虚拟助手
- 虚拟管家
- 原创角色

角色可以拥有：

- 头部
- 身体
- 手臂
- 腿
- 眼睛
- 嘴巴
- 表情
- 发型
- 衣服

方便后续实现丰富动画。

## 3.2 二次元萌宠

例如：

- 猫
- 狗
- 狐狸
- 龙
- 兔子
- 小恶魔
- 原创生物

两者底层行为系统尽量统一。

也就是说：

> “人”和“宠物”只是外观不同，底层都是 Pet Entity。

---

# 4. 第一版人格系统

第一版提供两种人格。

## 4.1 温柔型

特点：

- 温和
- 细心
- 关注用户
- 说话柔和
- 偶尔主动关心用户
- 对用户的互动积极响应

示例：

> “你已经坐在这里很久啦，要不要休息一下？”

> “我刚刚看到你一直在忙，所以没有打扰你。”

## 4.2 务实型

特点：

- 理性
- 简洁
- 不过度撒娇
- 更关注用户正在做什么
- 偶尔提醒用户
- 对任务和效率比较敏感

示例：

> “这个文件你已经打开 40 分钟了，还没完成。”

> “先把这个事情做完，再玩。”

# 5. AI 系统设计

第一版不建议让大模型控制所有宠物行为，而采用：

# Hybrid AI Architecture

即：

> **本地行为系统负责“身体”，AI 负责“灵魂”。**

这样可以降低延迟、减少 API 调用，并保证离线时宠物仍能正常活动。

## 5.1 本地行为系统

负责：

- 走路
- 坐下
- 趴下
- 睡觉
- 看鼠标
- 追鼠标
- 随机活动
- 靠近窗口
- 跳跃
- 被拖动
- 情绪动画
- 环境互动

这些行为不依赖 AI。

## 5.2 AI 系统

AI 主要负责：

- 对话
- 理解用户意图
- 判断情绪
- 生成回复
- 根据人格说话
- 决定少量高层行为

示例：

```json
{
  "emotion": "concern",
  "action": "approach_user",
  "reply": "辛苦了。先把眼前这个做完，剩下的慢慢来。"
}
```

然后由本地行为系统执行：

```text
approach_user
↓
走到用户附近
↓
播放关心动画
↓
显示气泡
↓
播放语音
```

# 10. 窗口识别系统

宠物需要知道“哪里有窗口”。

系统维护类似下面的桌面结构：

```text
Desktop
 ├── Monitor 1
 │    ├── Window A
 │    ├── Window B
 │    └── Window C
 │
 └── Monitor 2
      ├── Window D
      └── Window E
```

宠物可以获得：

```text
Window Position
Window Size
Window State
Window Focus
```

从而实现：

> “跳到浏览器窗口上。”

或者：

> “坐到 VS Code 顶部。”

# 13. 鼠标互动

第一版重点实现：

## 13.1 点击

点击宠物后：

> 宠物看向鼠标。

## 13.2 拖动

用户抓住宠物：

> 宠物被拎起来。

动作流程：

```text
抓住
 ↓
惊讶
 ↓
跟随鼠标
 ↓
释放
 ↓
落地
```

## 13.3 鼠标靠近

当鼠标进入宠物附近：

> 宠物看向鼠标。

距离继续缩短：

> 宠物开始关注鼠标。

进一步：

> 宠物主动追鼠标。

# 14. 宠物与窗口交互

这是第一版的特色功能之一。

例如用户打开浏览器：

```text
发现窗口
 ↓
走过去
 ↓
跳到窗口边缘
 ↓
趴在窗口顶部
```

用户移动窗口：

> 宠物跟随窗口移动。

> 宠物掉下来。

这类细节能够强化“宠物真的生活在桌面上”的感觉。

# 26. Codex 开发原则

## 26.1 行为和 AI 解耦

AI 不允许直接控制底层窗口。

## 26.2 所有行为必须有状态机约束

AI 只能提出行为意图，例如：

```text
approach
play
sleep
talk
look
```

最终由本地 Behavior System 判断是否执行。

## 26.3 AI 不可用时宠物仍然正常运行

断网之后，宠物依然可以：

- 走路
- 睡觉
- 玩耍
- 互动

## 26.4 API Key 本地保存

不建立自己的云端 Key 中转服务。

## 26.5 桌面交互优先保证稳定性

宁可少几个炫酷功能，也不要出现：

- 宠物窗口卡死
- 宠物消失
- 无法拖动
- 遮挡正常操作
- 长时间运行后内存持续异常增长

# 27. 建议的第一版验收标准

第一版达到以下条件即可认为核心 MVP 完成：

1. 应用启动后可以显示透明、无边框宠物。
2. 宠物可以在桌面上自主移动。
3. 用户可以拖动宠物。
4. 宠物能够感知鼠标并做出至少 3 种反应。
5. 宠物能够停留在窗口顶部或边缘。
6. 宠物能够识别活动窗口并进行基础互动。
7. 宠物包含温柔和务实两种人格。
8. 用户可以配置 OpenAI Compatible API。
9. 用户可以进行文本对话。
10. AI 回复可以触发情绪与动作。
11. AI 不可用时本地行为系统仍可独立运行。
12. 软件具备系统托盘和退出机制。
13. 长时间运行不会明显影响电脑正常使用。
